Kata 10: API Tool

Requests to make in Postman or Bruno: status codes, query params, bodies, and bad requests

This kata happens in your API tool (Postman or Bruno in VS Code), so you check yourself.
Make a new collection called Katas. For each request: predict what you'll get, Send, then open Show what you should see. Tick the box when yours matches.
Postman's JSON hard to read? GET requests also work in a browser tab.

Drill A: GET and status codes

  • GET https://dummyjson.com/recipes/1 Predict: what's the status? How many ingredients?
    Show what you should see 200 OK. The name is "Classic Margherita Pizza", and ingredients has 6 items.
  • GET https://dummyjson.com/recipes/9999 Predict: what's the status?
    Show what you should see 404 Not Found, and a message: "Recipe with id '9999' not found". The server still answered, so in JavaScript fetch works and response.ok is false.
  • Send Rep 1 again. In the response, open the Headers tab and find content-type.
    Show what you should see application/json. That's the server saying "the body is JSON", which is why response.json() works.

Drill B: query params (the part after ?)

  • GET https://dummyjson.com/recipes?limit=3 Then open the Params tab (Bruno: Query). Change 3 to 5 there and Send.
    Show what you should see 200, a recipes list with 3 items, and "total": 50. Changing the Params tab changes the URL too: limit=5 gives 5 recipes.
  • GET https://dummyjson.com/recipes/search?q=pizza Predict: how many pizzas?
    Show what you should see 200 and "total": 2: Classic Margherita Pizza (id 1) and Italian Margherita Pizza (id 45).
  • Change q=pizza to q=taco. Predict: 200 or 404?
    Show what you should see 200 with "recipes": [] and "total": 0. An empty list isn't an error! The search worked, it just found nothing. Your page should still say so ("No recipes found").

Drill C: POST and the body

  • POST https://dummyjson.com/recipes/add Body → JSON (Postman: Body → raw → JSON): { "name": "Taco Rocket Special" }
    Show what you should see 201 Created and {"id": 51, "name": "Taco Rocket Special"}. (It's a practice server, so it doesn't really save it.)
  • Same URL and body, but change the method back to GET. Predict first!
    Show what you should see 404 and "Recipe with id 'add' not found". A GET reads add as a recipe number. In JavaScript, this is what happens when you forget method: "POST".
  • Back to POST. Change the body type from JSON to Text (same words), and Send.
    Show what you should see 201, but only {"id": 51}. The name is gone! The server didn't know the body was JSON, so it ignored it. In JavaScript, that's a missing "Content-Type": "application/json" header.

Drill D: a different API (Open-Meteo weather)

  • GET https://api.open-meteo.com/v1/forecast?latitude=30.27&longitude=-97.74&current=temperature_2m Find current_units. What unit is the temperature in?
    Show what you should see 200 and "temperature_2m": "°C" (Celsius). Now add a param in the Params tab: temperature_unit = fahrenheit. Send: "°F".
  • Change latitude to 999. Predict: what's the status?
    Show what you should see 400 Bad Request and a reason: "Latitude must be in range of -90 to 90°. Given: 999.0." 400s mean you asked wrong. Good APIs tell you what to fix.

Your turn (no answers here): make one GET to an API you picked in Week 5 (PokeAPI, PotterAPI, GitHub users, NASA images). Find one field you'd show on a page, and make one request that gives a 404.

Your ticks are saved in this browser only.
